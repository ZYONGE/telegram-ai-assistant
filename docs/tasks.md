# 작업 큐

**다음에 할 일은 이 문서 한 곳에만 적는다.** 세션을 시작하면 `CLAUDE.md`를 읽고 이 문서의 맨 위 `대기` 항목부터 본다.
지금까지 무엇이 되는지, 무엇이 연결돼 있는지는 `docs/progress.md`에 있다.

> 공개 저장소다. 개인정보·비밀값·학교를 특정하는 값을 이 문서에 적지 않는다 (CLAUDE.md 절대 규칙 12).

## 읽는 법

- 위에서부터 순서대로 한다. `선행`이 걸려 있으면 그것부터 끝낸다.
- 한 번에 한 항목만 한다. 끝나면 테스트를 돌리고 보고한 뒤 멈춘다 (CLAUDE.md 절대 규칙 3·4).
- 끝낸 항목은 지우지 말고 `상태`를 `완료 (YYYY-MM-DD)`로 바꾼다. 그래야 다음 세션이 배경을 안다.
- 새로 알게 된 할 일은 여기 맨 아래 `잔가지`에 적는다. 다른 문서에 흩어 놓지 않는다.

`상태`: `대기` · `진행 중` · `완료` · `막힘` · `보류`(조건이 갖춰지면 다시 한다) · `후순위`
`환경`: 적혀 있지 않으면 아무 개발 기기에서나 된다. 적혀 있으면 그 조건이 있어야 끝낼 수 있다.

### T-07 탐색 결과로 수집 범위를 자동으로 정하기
- 상태: 완료 (2026-09-20)
- 한 일: `app/collectors/eclass/scope.py`. 카탈로그 102개를 읽어 **가져올 것 28개(알림 13·브리핑 1·저장만 14), 끄는 것 49개**로 좁혔다. 알림으로 남은 것은 전체 공지·알림함·쪽지·할 일·과목 공지·과제·시험·온라인강의·실시간강의·팀프로젝트·학사일정이다.
- 정하는 순서: (1) 경로 → (2) 메뉴 이름 → (3) 목록인지·마감이 있는지. 규칙이 못 정한 것만 가벼운 모델에게 묻는다(실제로 1개). **모델이 꺼져 있어도 규칙만으로 끝까지 돈다.**
- 규칙을 짜며 잡은 것
  - `notice_view_form`처럼 주제 낱말이 든 **상세 화면**이 알림이 됐다 → 글 하나를 여는 화면은 무조건 제외.
  - 메인 화면·과목방 첫 화면에 "마감"이라는 글자가 있어 알림이 됐다 → 목록이 아니면 먼저 끈다.
  - 보낸 쪽지가 "쪽지"에 걸려 알림이 됐다 → 경로 규칙은 끄는 것부터 가린다(알림은 적을수록 좋다).
- 대화로 바꾼다: `eclass_scope`(보기) · `eclass_scope_set`(바꾸기, 확인 버튼). 사용자가 정한 것은 다시 정할 때 덮어쓰지 않고, 그날 과목방에 못 들어가도 남는다.
- 남는 것: 껍데기(`_list_form`)와 내용(`_list`)이 둘 다 목록에 잡힌다. 소스를 붙이는 T-09에서 짝을 하나로 묶는다.
- 선행: T-06
- 목표: **카탈로그를 보고 무엇을 어떻게 다룰지 비서가 스스로 정한다.** 사용자가 설정 파일에 콘텐츠 이름을 하나씩 적지 않는다.
- 설계
  - 카탈로그의 화면마다 처리 수준을 자동으로 붙인다.
    - `notify` — 알림 게이트를 거쳐 알린다 (급하면 즉시)
    - `brief` — 브리핑에만 넣는다
    - `store` — 저장만 하고, 물어보면 답한다
    - `off` — 건드리지 않는다
  - 정하는 순서: (1) 코드 규칙으로 뻔한 것을 먼저 (마감·기한이 있는 화면 → `notify`, 공지·알림 → `notify`, 자료·게시판 → `store`), (2) 규칙에 안 걸리는 화면만 가벼운 모델에게 분류를 맡긴다. 메뉴 이름은 외부에서 온 글자이므로 데이터로만 넘긴다 (절대 규칙 8).
  - 결과를 `private/eclass_scope.json`에 저장한다. 다음부터는 이 파일을 읽고, 새 화면이 생겼을 때만 다시 정한다.
  - 사용자는 대화로 바꿀 수 있게 한다: "게시판은 알리지 마" → 확인 버튼 뒤 저장. `config.toml`에는 기본 정책과 소스별 기본 주기만 둔다 (개인을 알아볼 수 있는 값 없음).
  - **알림이 넘치지 않게 하는 것이 이 항목의 핵심이다.** 전부 `notify`로 두면 하루 상한 5건을 오전에 다 쓴다.
- 손댈 곳: `app/collectors/eclass/scope.py`(새로), `app/tools/eclass.py`(새로, 범위 변경 도구), `config.toml`, `tests/collectors/`
- 완료 기준: 카탈로그 표본을 넣으면 처리 수준이 붙은 소스 목록이 나오는 테스트 통과. 모델 호출 없이 규칙만으로도 동작하는 경로가 있어야 한다(모델이 꺼져 있어도 수집이 죽지 않게).

### T-21 eClass 순수 HTTP 로그인 탐침 만들기
- 상태: 완료 (2026-09-21) — 개발 맥북에서 테스트 24개 추가, 전체 734개 통과
- 한 일: `scripts/eclass_http_probe.py`, `tests/test_eclass_http_probe.py`. 새 의존성 없음.
  - 모드가 셋이다: 1단계(계정 안 씀) · `--reuse-session`(봇이 저장한 브라우저 세션의 쿠키로 내용만, **로그인 안 함**) · `--login`(한 번만).
  - `--reuse-session`은 계획에 없던 것을 더했다. **로그인 문제와 내용 문제를 떼어 볼 수 있고, 로그인 시도를 쓰지 않는다.** 봇이 지금 `private/browser/eclass_session.json`에 저장하는 쿠키를 httpx에 싣는다.
  - 1단계가 "가공 있음"·"모름"이면 `--login`을 줘도 로그인하지 않는다(`--force`로만). 폼이 다른 사이트(SSO)로 보내면 `--force`로도 하지 않는다.
  - 내용 확인은 봇과 같은 요청이다: 수집기의 상수(`TODO_FORM_DATA` 등)와 파서를 그대로 가져다 쓰고, 화면 안 fetch처럼 `X-Requested-With`와 직전 화면 `Referer`를 붙인다.
  - 조회 규칙은 탐색기의 `safe_path`·`UNSAFE_WORDS`를 그대로 쓴다.
  - 머리글에 문자셋이 없으면 화면의 meta를 보고 디코딩한다. 본 문자셋을 결과에 적는다 (T-23 httpx 세션에 필요).
- 만들며 알게 된 것
  - **httpx는 INFO 로그에 요청 주소를 통째로 찍는다.** 학교 주소가 새지 않게 탐침이 httpx 로거를 WARNING으로 낮춘다. 봇 본체(`app/main.py`)는 이미 그렇게 한다. **T-23에서 httpx 세션을 봇에 넣을 때도 이 규칙이 살아 있는지 확인한다.**
  - 로그인 화면에는 평소에도 숨은 `reCaptcha` 칸이 있어 낱말만으로는 추가 인증을 가릴 수 없다. 탐침은 걸렸을 때만 나타나는 reCAPTCHA 스크립트·위젯을 본다. 봇의 `classify_login()`은 낱말로 보는데, 로그인 실패 뒤 **로그인 화면**으로 돌아오는 경우가 있다면 실패를 추가 인증으로 잘못 볼 수 있다 (실제 사이트는 실패해도 메인으로 보내므로 지금은 드러나지 않는다). 잔가지에 적었다.
- 목표: 브라우저 없이 httpx + 세션 쿠키만으로 eClass에 로그인하고 내용을 받을 수 있는지 **증거를 모으는 도구**를 만든다.
- 이미 아는 위험 두 가지 (`docs/refs/eclass-cli.md` 6단계 확인, `docs/refs/eclass-paths.md` 1절)
  1. 로그인 폼(`POST /ilos/lo/login.acl`)에 히든 필드 `challenge`·`response`가 있다. 로그인 단추의 자바스크립트(`loginForm()`)가 비밀번호를 가공해 `response`를 만든다면 그 계산을 파이썬으로 옮겨야 한다.
  2. 내용 주소(`..._list.acl`)를 "브라우저 밖에서" 부르면 세션이 끊겼다는 답이 왔다. 쿠키가 없어서였는지, `X-Requested-With`·`Referer` 머리글이 없어서였는지 가리지 않았다.
- 설계: `scripts/eclass_http_probe.py`. 단계를 나눠 **로그인 시도를 아낀다** (학교 계정은 연속 실패에 잠길 수 있다).
  - 1단계(계정 안 씀): 로그인 화면을 받아 폼 구조와 `loginForm()` 자바스크립트를 읽고, 비밀번호를 가공하는지 판정한다.
  - 2단계(`--login`을 줄 때만, 한 번만 시도): 폼대로 로그인 → 메인 화면에 로그아웃 표시가 있는지 → 세 가지 요청 방식(한 번에 / 껍데기+내용 / 과목방)을 차례로 확인한다.
  - 메모리(최대 RSS)와 걸린 시간을 함께 적는다. 서버 부하 설계의 근거가 된다.
  - 결과와 로그인 화면 자바스크립트는 `private/eclass_probe/`에 남긴다. 화면에 찍는 것은 경로·판정뿐이고 학교 주소·계정·쿠키는 찍지 않는다 (절대 규칙 7·12).
- 손댈 곳: `scripts/eclass_http_probe.py`(새로), `tests/test_eclass_http_probe.py`(새로). 새 의존성 없음 (httpx·BeautifulSoup은 이미 있다).
- 완료 기준: 가짜 응답(`httpx.MockTransport`)으로 도는 테스트 통과. 실제 실행은 T-22.

### T-22 탐침을 실제 계정으로 돌리기
- 상태: 대기
- 선행: T-21
- 환경: **`private/`가 있는 기기.** 지금은 윈도우 PC. 서버 맥북에어로 `private/`를 옮긴 뒤라면 거기서 해도 된다(서버에서 직접 재는 편이 낫다).
- 하는 법 (윈도우에서는 `uv` 앞에 `py -3.14 -m`을 붙인다)
  1. `git pull`
  2. `uv run python -m scripts.eclass_http_probe` — 1단계만. 계정을 쓰지 않는다.
  3. `uv run python -m scripts.eclass_http_probe --reuse-session` — 로그인하지 않고 내용만. **봇이 eClass를 한 번 수집한 직후에** 해야 저장된 세션이 살아 있다.
  4. 1단계가 "가공 없음"일 때만 `--login`. "가공 있음"이면 **로그인하지 말고** `private/eclass_probe/login_form.js`를 보고 계산을 옮긴다 (T-21로 돌아간다).
  - 결과는 `private/eclass_probe/`(report.json, login_page.html, login_form.js)에 남는다. 화면 출력의 "판정" 줄이 T-23의 어느 갈래인지 알려 준다.
  - 봇이 같은 계정으로 돌고 있으면 `--login`이 봇의 세션을 끊을 수 있다. 봇은 다음 수집 때 다시 로그인하므로 문제는 없지만, 그 한 번이 로그인 횟수에 더해진다.
- 완료 기준: 네 가지에 답이 나온다. ① 로그인이 HTTP로 되는가 ② 껍데기+내용 방식이 httpx로 받아지는가 ③ 과목방에 httpx로 들어가지는가 ④ 수집 한 번의 최대 메모리. 답을 이 항목에 적는다.

### T-23 수집 세션 계층 정하기
- 상태: 대기
- 선행: T-22
- 목표: T-22 결과에 따라 `app/collectors/eclass/session.py`를 정한다.
- 바꾸기 쉬운 이유: 소스·파서·탐색기가 세션에서 쓰는 것은 `start` · `close` · `ensure_login` · `open(path)` · `post(path, data)` · `enter_course(key)` 여섯 개뿐이다 (2026-09-21 확인). **이 모양만 맞추면 소스와 파서는 손대지 않는다.**
- 갈래
  - (가) 로그인·내용 모두 HTTP로 된다 → httpx 세션을 새로 만들어 바꿔 끼운다. 쿠키는 지금처럼 `private/`에 저장해 재사용한다. Playwright를 의존성에서 뺄지 정한다 (빼면 `playwright install chromium`도 필요 없다).
  - (나) 내용은 HTTP로 되는데 로그인만 안 된다 → **로그인만 브라우저로 하고 받은 쿠키를 httpx로 넘긴다.** 세션을 재사용하므로 크로미움은 세션이 만료될 때만 잠깐 뜬다. 지금 저장하는 `private/browser/eclass_session.json`에 쿠키가 이미 들어 있다.
  - (다) 내용도 HTTP로 안 된다 → Playwright를 유지하고 메모리를 줄인다. 지금도 수집할 때만 띄우고 닫는다. 수집 주기를 늘리고, 한 번에 탭 하나만 쓰고, 크로미움 메모리 옵션을 본다.
- 완료 기준: 기존 eClass 테스트 전부 통과 + 실제 계정으로 1회 수집 + 수집 중 최대 메모리를 T-22 값과 비교해 적는다.

### T-24 맥북에어 서버 기본 설정
- 상태: 대기
- 환경: **서버 맥북에어 M1**
- 할 일
  - uv 설치 → 저장소 받기 → `git config core.hooksPath .githooks` → `uv sync --no-dev`
  - `private/`를 **git이 아니라 직접** 옮긴다 (AirDrop·USB). DB는 윈도우 쪽 봇을 멈춘 뒤 옮긴다. **두 기기에서 봇을 동시에 돌리지 않는다** — 같은 토큰으로 long polling을 둘이 하면 서로 메시지를 빼앗는다.
  - 잠자기 끄기(`sudo pmset -a disablesleep 1`, 사용자 허용). 시간대 확인.
- **정해야 할 것 두 가지**
  - **FileVault**: 켜져 있으면 재부팅 뒤 암호를 넣기 전까지 디스크가 잠겨 있어 봇이 뜨지 않는다. 계획된 재시작은 `sudo fdesetup authrestart`로 넘길 수 있지만 정전·강제 재시작 뒤에는 사람이 필요하다. 끄면 `private/`(토큰·학교 계정)를 지키는 층이 하나 줄어든다. 사용자가 고른다.
  - **macOS 자동 업데이트**: 자동 설치가 켜져 있으면 밤사이 재시동하고, FileVault가 켜져 있으면 거기서 멈춘다. 자동 설치를 끄고 손으로 올리는 편이 안전하다.
- 완료 기준: 서버에서 `uv run pytest` 통과, 봇을 손으로 한 번 띄워 텔레그램 대화가 된다.

### T-25 launchd로 상시 실행
- 상태: 대기
- 선행: T-24
- 손댈 곳: `deploy/macos/` (새로) — LaunchDaemon plist, 설치·제거 안내. plist 작성은 어느 기기에서나 되고, 설치는 서버에서.
- 정할 것
  - `/Library/LaunchDaemons/`에 둔다 → 부팅하면 로그인 없이 뜬다. 기본은 root로 뜨므로 `UserName`으로 일반 사용자로 내린다.
  - `KeepAlive`는 `{SuccessfulExit = false}`로 — **비정상 종료일 때만** 다시 띄운다. 설정 오류로 바로 죽는 경우(`main.py`가 종료 코드 1로 끝난다)에는 되살아나 봐야 또 죽으므로 `ThrottleInterval`로 간격을 둔다.
  - `WorkingDirectory`는 저장소, 실행은 `.venv`의 파이썬을 직접 (uv를 거치지 않으면 뜰 때 메모리가 조금 덜 든다).
  - 표준 출력·오류는 T-17 로그 파일과 겹치지 않게 정리한다.
- 완료 기준: 재부팅 뒤 로그인하지 않아도 봇이 대답한다. 프로세스를 강제로 죽이면 다시 뜬다.

  - 나머지는 안전했다. 날씨·구글·eClass 예외 메시지는 모두 우리가 쓴 문장이라 좌표·키·본문이 들어가지 않는다 (`WeatherUnavailable`은 그렇게 만들도록 모듈 주석에 적혀 있다). 예외는 대부분 종류 이름(`type(exc).__name__`)만 남긴다.
- 테스트 3개 (파일에 남는다 / 끌 수 있다 / 못 열어도 뜬다).
- 선행: T-14
- 파일로 남기고 회전시킨다. 개인정보·비밀값이 로그에 들어가지 않는지 한 번 훑는다 (좌표, 메일 본문, 쪽지, 학교 계정).

## 잔가지

급하지 않지만 잊으면 안 되는 것들. 관련 작업을 할 때 같이 처리한다.

- ~~맥북 개발 환경 만들기~~ 개발 맥북에 만들었다 (2026-09-21): `brew install uv` → `uv sync` → 전체 테스트 통과. `private/` 없이 된다. 서버 맥북에어도 같은 절차다 (T-24).
- 봇의 `classify_login()`(`app/collectors/eclass/session.py`)은 로그인 뒤 화면에 "recaptcha" 낱말이 있으면 추가 인증으로 본다. 로그인 화면에는 평소에도 숨은 `reCaptcha` 칸이 있으므로, 실패 뒤 **로그인 화면**으로 돌아오는 경우가 생기면 단순 실패를 추가 인증으로 잘못 알린다. 지금은 실제 사이트가 실패해도 메인으로 보내 드러나지 않는다. T-23에서 세션 계층을 손볼 때 탐침의 `captcha_shown()`처럼 스크립트·위젯으로 보게 바꾼다.
- **개인 파일은 저장소에 넣지 않는다. 암호화해도 마찬가지다.** 공개 저장소라 한 번 올라가면 사본이 어디까지 퍼졌는지 알 수 없다. 기기 사이에 옮길 일이 있으면 git 말고 직접 옮긴다(USB·AirDrop·서버 경유 scp). 서버가 생기면 거기가 `private/`의 유일한 집이 된다.
- google-genai가 Python 3.17에서 없어질 문법을 쓴다는 경고가 난다. 지금 동작에는 영향이 없다. SDK를 올릴 때 확인한다.
- 대화 요약에 "진행 중인 요청: 없음" 같은 빈 줄이 섞인다. 요약 프롬프트를 손본다.
- 무료 티어에서는 Gemini 웹 검색(그라운딩)이 막힐 수 있다. 실제로 막히면 별도 검색 API로 바꾼다.
- 보관함 검색이 낱말 포함 방식이다. 느려지면 SQLite FTS5로 바꾼다 (T-08과 같은 문제라 함께 처리해도 된다).
- eClass 온라인강의 목록(`/ilos/st/course/online_list.acl`)이 빈 응답을 준다. 요청 방식을 더 봐야 한다. 마감은 할 일 화면이 이미 알리므로 급하지 않다. 강의별 진도·출석률까지 보고 싶어질 때 처리한다 (T-06에서 발견, ADR 0007에도 적혀 있음). **환경: 윈도우 PC**(실제 계정 필요).
- 위치를 손대지 않고 받으려면, 서버 배포(T-14) 뒤에 휴대폰 자동화가 좌표를 서버의 작은 수신 주소로 보내는 방식을 붙인다. 비밀 토큰으로만 받고 좌표는 `private/` DB에만 둔다.
- ~~과거 커밋에 남은 개인정보~~ 처리 완료 (2026-09-19). 기록을 다시 쓰고 저장소를 새로 올려 옛 커밋 주소까지 막았다. 작성자 정보도 전부 noreply 한 사람으로 통일했다. 앞으로는 커밋 검사 훅이 막는다.
