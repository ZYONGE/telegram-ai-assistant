# 작업 큐

**다음에 할 일은 이 문서 한 곳에만 적는다.** 세션을 시작하면 `CLAUDE.md`를 읽고 이 문서의 맨 위 `대기` 항목부터 본다.
지금까지 무엇이 되는지, 무엇이 연결돼 있는지는 `docs/progress.md`에 있다.

> 공개 저장소다. 개인정보·비밀값·학교를 특정하는 값을 이 문서에 적지 않는다 (CLAUDE.md 절대 규칙 12).

## 읽는 법

- 위에서부터 순서대로 한다. `선행`이 걸려 있으면 그것부터 끝낸다.
- 한 번에 한 항목만 한다. 끝나면 테스트를 돌리고 보고한 뒤 멈춘다 (CLAUDE.md 절대 규칙 3·4).
- 끝낸 항목은 지우지 말고 `상태`를 `완료 (YYYY-MM-DD)`로 바꾼다. 그래야 다음 세션이 배경을 안다.
- 새로 알게 된 할 일은 여기 맨 아래 `잔가지`에 적는다. 다른 문서에 흩어 놓지 않는다.

`상태`: `대기` · `진행 중` · `완료` · `막힘` · `후순위`
`환경`: 적혀 있지 않으면 아무 개발 기기에서나 된다. 적혀 있으면 그 조건이 있어야 끝낼 수 있다.

### T-07 탐색 결과로 수집 범위를 자동으로 정하기
- 상태: 완료 (2026-09-20)
- 한 일: `app/collectors/eclass/scope.py`. 카탈로그 102개를 읽어 **가져올 것 28개(알림 13·브리핑 1·저장만 14), 끄는 것 49개**로 좁혔다. 알림으로 남은 것은 전체 공지·알림함·쪽지·할 일·과목 공지·과제·시험·온라인강의·실시간강의·팀프로젝트·학사일정이다.
- 정하는 순서: (1) 경로 → (2) 메뉴 이름 → (3) 목록인지·마감이 있는지. 규칙이 못 정한 것만 가벼운 모델에게 묻는다(실제로 1개). **모델이 꺼져 있어도 규칙만으로 끝까지 돈다.**
- 규칙을 짜며 잡은 것
  - `notice_view_form`처럼 주제 낱말이 든 **상세 화면**이 알림이 됐다 → 글 하나를 여는 화면은 무조건 제외.
  - 메인 화면·과목방 첫 화면에 "마감"이라는 글자가 있어 알림이 됐다 → 목록이 아니면 먼저 끈다.
  - 보낸 쪽지가 "쪽지"에 걸려 알림이 됐다 → 경로 규칙은 끄는 것부터 가린다(알림은 적을수록 좋다).
- 대화로 바꾼다: `eclass_scope`(보기) · `eclass_scope_set`(바꾸기, 확인 버튼). 사용자가 정한 것은 다시 정할 때 덮어쓰지 않고, 그날 과목방에 못 들어가도 남는다.
- 남는 것: 껍데기(`_list_form`)와 내용(`_list`)이 둘 다 목록에 잡힌다. 소스를 붙이는 T-09에서 짝을 하나로 묶는다.
- 선행: T-06
- 목표: **카탈로그를 보고 무엇을 어떻게 다룰지 비서가 스스로 정한다.** 사용자가 설정 파일에 콘텐츠 이름을 하나씩 적지 않는다.
- 설계
  - 카탈로그의 화면마다 처리 수준을 자동으로 붙인다.
    - `notify` — 알림 게이트를 거쳐 알린다 (급하면 즉시)
    - `brief` — 브리핑에만 넣는다
    - `store` — 저장만 하고, 물어보면 답한다
    - `off` — 건드리지 않는다
  - 정하는 순서: (1) 코드 규칙으로 뻔한 것을 먼저 (마감·기한이 있는 화면 → `notify`, 공지·알림 → `notify`, 자료·게시판 → `store`), (2) 규칙에 안 걸리는 화면만 가벼운 모델에게 분류를 맡긴다. 메뉴 이름은 외부에서 온 글자이므로 데이터로만 넘긴다 (절대 규칙 8).
  - 결과를 `private/eclass_scope.json`에 저장한다. 다음부터는 이 파일을 읽고, 새 화면이 생겼을 때만 다시 정한다.
  - 사용자는 대화로 바꿀 수 있게 한다: "게시판은 알리지 마" → 확인 버튼 뒤 저장. `config.toml`에는 기본 정책과 소스별 기본 주기만 둔다 (개인을 알아볼 수 있는 값 없음).
  - **알림이 넘치지 않게 하는 것이 이 항목의 핵심이다.** 전부 `notify`로 두면 하루 상한 5건을 오전에 다 쓴다.
- 손댈 곳: `app/collectors/eclass/scope.py`(새로), `app/tools/eclass.py`(새로, 범위 변경 도구), `config.toml`, `tests/collectors/`
- 완료 기준: 카탈로그 표본을 넣으면 처리 수준이 붙은 소스 목록이 나오는 테스트 통과. 모델 호출 없이 규칙만으로도 동작하는 경로가 있어야 한다(모델이 꺼져 있어도 수집이 죽지 않게).

- 한 일: 마이그레이션 9로 `eclass_items`에 `body`·`posted_at`·`source`를 더하고, `EclassRepository.search()`와 모델 도구 `eclass_search`를 붙였다. 과목·기간·낱말로 찾는다. 조회라서 확인 버튼 없이 바로 실행한다.
- 정한 것
  - 낱말은 제목·본문·과목에서 **모두** 포함하는 글만 찾는다 (보관함 검색과 같은 방식).
  - 기간은 글이 올라온 시각을 먼저 보고, 없으면 처음 본 시각으로 대신한다. 올라온 시각을 못 읽는 화면이 있다.
  - 본문을 늦게 읽어 오는 경우가 있어(목록에서 제목만 먼저 본다), 빈 본문으로 기존 본문을 지우지 않는다.
  - 도구 결과 첫 줄에 "학교 사이트에서 가져온 내용"이라고 밝힌다 (절대 규칙 8).
- 확인: 실제 DB 마이그레이션 8→9, 기존 12건 유지. "과제"로 찾으면 마감이 붙은 4건이 나온다.
- 남는 것: 본문은 아직 비어 있다. 목록 화면을 붙이는 T-09부터 채워진다.
- 선행: T-04
- 목표: 모은 내용을 실제로 꺼내 쓸 수 있게 한다. "자료구조 지난주 공지 뭐였지?"에 답하는 것이 목표다.
- 설계
  - `eclass_items`에 `body`(본문) · `posted_at`(올라온 시각) · `source`(카탈로그 키) 열을 추가하는 마이그레이션.

  - 본문은 외부에서 온 글이다. 도구 결과에 "외부 데이터"로 표시해 넘긴다 (절대 규칙 8).

### T-09 목록형 화면 수집 붙이기 (공지·게시판·쪽지)
- 상태: 완료 (2026-09-20)
- 한 일: 일반 목록 파서(`parse_list`)와 `BoardSource`를 만들고, 카탈로그·수집 범위에서 소스를 자동으로 만든다(`sources/build.py`). 실제 계정으로 **전체 공지 22건·과목 공지 15건(본문 5건)·쪽지 10건**을 모았고, "휴강"으로 찾으면 본문까지 나온다.
- 파서: 표에서 칸이 둘 이상인 줄만 센다. 글번호는 화면마다 이름이 달라(`ARTL_NUM`·`RT_SEQ`·확인란) 차례로 본다. 쪽지함은 연도 없이 "09.17 오후 1:52"로 적어서, 한 달 넘게 앞선 날로 읽히면 지난해로 본다.
- 본문: **알릴 화면의 새 글만** 한 번에 5건까지 읽어 온다. 글마다 화면을 한 번 더 열어야 해서 값이 비싸다.
- 돌리면서 잡은 것
  - 처음 보는 게시판에 쌓여 있던 지난 글까지 전부 새 글로 알렸다(이벤트 32건) → 처음 볼 때는 7일 안의 글만 알리고 나머지는 조용히 담는다. 올린 시각이 없는 항목(할 일)은 그대로 알린다.
  - 알릴 화면이 7개라 저장용 화면이 영영 밀렸다 → **오래 기다린 것부터** 돌린다. 한 번에 8개, 그중 과목방 화면은 2개까지.
  - 과제·시험·온라인강의는 할 일 화면이 이미 알린다 → 과목방 게시판은 저장만 한다(같은 것을 두 번 알리지 않는다).
  - 수강 과목·시간표 화면을 게시판으로 읽어 "구조가 바뀐 것 같다"고 잘못 보고했다 → 게시판이 아닌 화면은 끈다.
- 선행: T-06, T-07, T-08
- 목표: 카탈로그에 잡힌 목록형 화면을 한 파서로 처리한다.
- 설계: eClass의 게시판 화면은 대체로 같은 모양(글번호가 든 표 + 제목 링크 + 날짜)이다. `parse_notices()`가 이미 그 모양을 읽는다. 이것을 **일반 목록 파서**로 넓혀 공지·자료실·열린 게시판·쪽지에 함께 쓴다. 화면마다 다른 점만 소스에서 채운다.
- 이미 있는 것: `app/collectors/eclass/parse.py`의 `parse_notices()` · `parse_courses()` · `parse_course_select()`와 그 테스트. 만들어 뒀지만 아직 아무도 쓰지 않는다. 연결하는 것이 이 항목이다.
- 쪽지 주의: 개인 메시지다. 본문은 `private/` 안 DB에만 두고 로그에 남기지 않는다.
- 완료 기준: 표본 HTML로 도는 테스트 통과 + 윈도우 PC에서 실제 1회 수집 확인.
