# ADR 0008 — 8단계 결정: 임시 서버를 맥북에어 M1로 (Oracle Cloud A1 보류)

- 날짜: 2026-09-21
- 상태: 채택 (임시. A1 인스턴스를 확보하면 이전한다)
- 관련: CLAUDE.md 3절(기술 스택), 9절(8단계), `deploy/README.md`(A1 도커 배포), ADR 0007(eClass 수집)

## 배경

8단계는 Oracle Cloud Always Free의 Ampere A1(arm64, Ubuntu 24.04)에 Docker Compose로 올리는 것을 기준으로 설계했다
(`deploy/Dockerfile`, `deploy/compose.yaml`, T-13·T-14).

- 무료 A1 인스턴스 생성이 **수십 회 실패**했다. 원인은 무료 ARM 용량 부족이다.
- 유료 계정으로 올려 보았지만 provisioning 대기에서 더 나아가지 않았다.
- 비서는 켜져 있어야 뜻이 있다. 서버를 기다리는 동안 브리핑·수집·리마인더가 멈춰 있다.

## 결정

사용자가 가진 **맥북에어 M1 2020 (8GB / 512GB)** 을 임시 서버로 쓴다. 평소 취미·콘텐츠 소비용 보조 기기라 비서에 내줄 수 있다.
나중에 A1 인스턴스를 확보하면 옮긴다. **옮기기 쉽게 설계하는 것이 이 결정의 조건이다.**

### 1. 기기 제약 (사용자가 받아들인 것)

| 제약 | 내용 |
|---|---|
| 네트워크 | Wi-Fi. 기기를 옮기면 끊길 수 있고, 그동안 봇이 멈추는 것은 감수한다 |
| 잠자기 | 잠자기 끄기(`pmset disablesleep`)는 허용한다 |
| 수명 | 기기 수명을 깎는 무거운 상시 작업은 들이지 않는다 |
| 메모리 | **8GB다. 스왑이 생기면 교체할 수 없는 SSD의 수명을 쓴다.** 메모리 상주량을 낮게 유지하는 것이 설계의 첫 기준이다 |
| 준비된 것 | 최신 macOS 지원 확인, 배터리 충전 상한 설정 완료 |

### 2. 기술 결정

| 항목 | 결정 | 이유 |
|---|---|---|
| 실행 환경 | **Docker Desktop을 쓰지 않는다.** 네이티브 Python 가상환경(uv가 만드는 `.venv`, `uv.lock` 그대로) | macOS의 Docker는 리눅스 VM을 통째로 띄운다. VM이 상주하며 메모리를 잡는다 |
| 프로세스 관리 | **launchd LaunchDaemon + `KeepAlive`** | 부팅하면 로그인 없이 뜨고, 비정상 종료되면 다시 띄운다. macOS에 원래 있는 것이라 더 깔 것이 없다 |
| 텔레그램 | long polling (지금과 같다) | 서버가 먼저 텔레그램에 연결하므로 공인 IP·포트포워딩·DDNS가 필요 없다. 가정용 Wi-Fi에서 그대로 된다 |
| eClass 수집 | **httpx + BeautifulSoup을 먼저 검토한다.** 헤드리스 브라우저(Playwright)는 순수 HTTP로 안 될 때만 | 크로미움은 뜰 때마다 수백 MB를 쓴다. 수집 때만 떴다 닫히므로 상주는 아니지만, 그 순간의 피크가 8GB에서 스왑을 부를 수 있다 |
| 주기 작업 | 상시 루프가 아니라 스케줄 기반. 조용한 시간(23:00~06:30)에는 건너뛰거나 주기를 늘린다 | 지금 구조(APScheduler, 조용한 시간 건너뛰기)가 이미 그렇다. 새로 넣는 작업도 이 방식을 따른다 |
| 원격 관리 | SSH + Tailscale | 포트를 밖에 열지 않고 들어간다 |

### 3. 무엇이 먼저인가

**eClass 로그인이 순수 HTTP 요청(세션 쿠키)만으로 되는지부터 확인한다 (T-21·T-22).** 그 결과에 따라 서버 부하 설계가 갈린다.

- 된다 → 크로미움을 걷어낸다. 수집 때 늘어나는 메모리가 수십 MB 수준으로 줄어든다.
- 안 된다 → Playwright를 두되 메모리를 줄이는 쪽으로 간다 (T-23).

6단계에서 이미 알고 있던 위험 두 가지가 있다 (`docs/refs/eclass-cli.md`, `docs/refs/eclass-paths.md`).

- 로그인 폼에 히든 필드 `challenge`·`response`가 있다. 로그인 단추의 자바스크립트가 비밀번호를 가공해 `response`를 만든다면, 그 계산을 파이썬으로 옮겨야 한다.
- 목록 내용 주소(`..._list.acl`)를 "브라우저 밖에서" 부르면 세션이 끊겼다는 답이 왔다. 이것이 쿠키가 없어서였는지, `X-Requested-With`·`Referer` 같은 머리글이 없어서였는지는 가리지 않았다.

## 원래 계획(OCI A1 + Docker)과 다르게 한 점

| 원래 | 지금 | 이유 |
|---|---|---|
| Docker Compose로 띄운다 | 네이티브 venv + launchd | 8GB에서 VM 상주를 피한다 |
| 리눅스(Ubuntu 24.04) arm64 | macOS arm64 | 같은 arm64라 파이썬 휠은 대체로 같다. 대신 프로세스 관리(systemd·도커 ↔ launchd)와 경로가 다르다 |
| 이미지 안에 크로미움을 넣는다 | 크로미움 없이 가는 것을 먼저 검토한다 | 메모리 |
| 데이터센터 유선망, 고정 가동 | 가정용 Wi-Fi, 끊김 감수 | 기기 사정 |
| 서버 IP가 해외(일본)라 학교 eClass가 받아 줄지 불확실 | 국내 가정용 IP | **이 위험은 사라진다** |

## 결과

- `deploy/Dockerfile`·`compose.yaml`·`README.md`는 지우지 않는다. A1으로 옮길 때 다시 쓴다. T-13·T-14는 `보류`로 둔다.
- macOS용 실행 파일은 `deploy/macos/`에 둔다 (T-25).
- `private/`는 서버 맥북에어로 **git이 아니라 직접** 옮긴다 (`docs/tasks.md` 잔가지의 원칙). 서버가 생기면 그곳이 `private/`의 집이 된다.
- 개발 기기와 서버 기기가 다르다. 세션이 도는 기기가 서버인지 먼저 확인한다 (`sysctl hw.model`, `sysctl hw.memsize`).

## A1으로 옮길 때

1. A1 인스턴스를 확보하면 `deploy/README.md` 순서대로 도커로 띄운다.
2. 맥북에어의 `private/`를 서버로 옮긴다. DB는 봇을 멈춘 뒤 옮긴다 (SQLite를 열린 채로 복사하면 깨질 수 있다).
3. 맥북에어의 LaunchDaemon을 내린다. **두 곳에서 동시에 돌리지 않는다** — 같은 봇 토큰으로 두 곳이 long polling을 하면 서로 업데이트를 빼앗는다.
4. eClass를 httpx로 바꿨다면 도커 이미지에서 크로미움을 뺄 수 있다. 이미지가 크게 가벼워진다.
