# ADR 0005 — 4단계 결정: 날씨, 웹 검색, 보관함, 주간 계획

- 날짜: 2026-09-18
- 상태: 채택
- 관련: CLAUDE.md 6절(역할별 세부 규칙), 4-1절(통합 설계 원칙), ADR 0004(모델 호출)

## 배경

4단계는 외부 계정 연동 없이 붙일 수 있는 기능 네 가지다. 각각 다른 외부 자원을 쓰지만, 결과물은 하나의 비서여야 한다.

## 결정

### 1. 날씨: 기상청 단기예보 API

- 조회는 `app/collectors/weather.py`에서만 한다. 모델에는 정리된 문장만 넘어간다.
- **옷차림은 코드의 기온 구간표로 정한다.** 모델은 문장만 다듬는다 (CLAUDE.md 6절). 기준 기온은 아침·점심·저녁 중 가장 낮은 값이고, 일교차 8도 이상이면 겉옷, 강수확률 60% 이상이거나 강수 형태가 있으면 우산을 덧붙인다.
- 인증키는 `private/.env`(`WEATHER_API_KEY`), 동네 좌표와 지역 이름은 `private/local.toml`에 둔다. **둘 중 하나라도 없으면 날씨 기능만 꺼지고 비서는 그대로 동작한다.**
- 위경도만 아는 경우를 위해 기상청이 공개한 격자 변환식(람베르트 정각원뿔도법)을 코드로 옮겼다.
- 실패는 `WeatherUnavailable`로 알린다. 예외 메시지와 로그에 인증키가 들어간 주소를 넣지 않는다.
- 접점: 브리핑은 `BriefingProvider`(아침에는 오늘 날씨·옷차림, 저녁에는 내일 날씨 한 줄), 대화는 `get_weather` 도구. 두 경로가 같은 수집기를 쓴다.

### 2. 웹 검색: Gemini의 Google 검색 그라운딩

대안은 검색 API를 따로 붙이는 것(Brave, Tavily 등)이었다. 그라운딩을 고른 이유는 키와 의존성을 늘리지 않고, 결과 요약까지 한 번에 끝나기 때문이다.

- 제공사 SDK는 `app/llm/` 안에만 둔다는 규칙에 맞춰, `WebSearch` 약속을 `app/llm/base.py`에 두고 Gemini 어댑터가 구현한다. 도구(`app/tools/search.py`)는 약속만 쓴다.
- **대화 루프와 분리된 별도 호출**이다. 도구 호출(function calling)과 검색 도구를 한 요청에 섞지 않는다.
- 결과 앞에 "외부에서 온 참고 자료"라고 붙이고 출처를 최대 5개까지 함께 돌려준다 (절대 규칙 8).
- `[llm.gemini] web_search = false`로 끄면 도구가 꺼져 있다고 답한다. 제공사를 바꾸면 그 어댑터가 검색을 구현하지 않는 한 `LLM.search`는 None이다.
- 남은 점: 무료 티어에서는 그라운딩 호출이 제한될 수 있다. 실패하면 도구가 짧은 오류 문구를 돌려주고 비서는 계속 동작한다.

### 3. 보관함: SQLite 표 하나 + 페이지 본문 추출

- `archive_items` 표 하나에 링크와 메모를 모은다 (마이그레이션 4). 할 일·일정과 섞지 않는다. 사진·음성은 저장하지 않는다.
- 링크는 `app/collectors/webpage.py`가 HTML에서 제목과 본문 글자만 뽑고, 가벼운 모델이 세 문장 이하로 요약한다. 요약에 실패해도 저장은 그대로 된다.
- 내부망 주소(localhost, 사설 IP, `.local`)는 가져오지 않는다. 글이 아닌 파일과 400KB를 넘는 부분은 버린다.
- 검색은 제목·요약·본문·태그를 낱말별로 모두 포함하는지 보는 방식이다. 개인 규모에서는 이것으로 충분하고, 느려지면 FTS5로 바꾼다.
- 저장은 즉시 실행, 삭제는 확인 버튼이다 (할 일 삭제와 같은 기준, CLAUDE.md 7절).

### 4. 주간 계획: 브리핑 종류 하나 추가

- 새 발송 경로를 만들지 않고 `BriefingKind.WEEKLY`로 처리한다. 알림 게이트·중복 방지·발송이 아침·저녁 브리핑과 같은 길을 쓴다 (4-1절).
- 각 제공자는 주간 분기를 하나씩 더 갖는다. 할 일은 다음 주(월~일) 마감·지난 마감·마감 없는 할 일, 예약 작업은 다음 주 실행분을 낸다.
- **새 소식은 주간 계획에 넣지 않는다.** 일요일 21시에 가져가면 22시 저녁 브리핑에서 빠지기 때문이다.
- 요일별 배치는 모델이 한다. 다듬기 프롬프트를 주간용으로 따로 두되 "초안에 있는 사실만 쓴다"는 제약은 같다. 회고 기능은 만들지 않는다 (6절).
- 시각은 `[briefing] weekly`(기본 21:00)이고 요일은 일요일로 고정한다.

## 원본·기존 설계와 다르게 한 점

- 날씨 옷차림을 모델에게 맡기지 않고 코드 표로 고정했다. 같은 기온에 매번 다른 답이 나오지 않게 하기 위해서다.
- 검색을 별도 API가 아니라 모델 제공사의 그라운딩으로 붙였다. 대신 제공사를 바꾸면 검색이 함께 빠질 수 있다는 점을 받아들였다.
- 보관함을 기억(`memory.md`)과 분리했다. 기억은 사용자에 대한 짧은 사실, 보관함은 나중에 찾아볼 자료다.
