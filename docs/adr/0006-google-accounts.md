# ADR 0006 — 5단계 결정: Google 계정 연동 (캘린더·Gmail)

- 날짜: 2026-09-18
- 상태: 채택
- 관련: CLAUDE.md 6절(메일·일정 규칙), 4-1절(통합 설계 원칙), 8절(Inbox Zero 참고), ADR 0005

## 배경

캘린더와 메일은 계정 인증이 필요한 첫 기능이다. 사용자는 Google 계정 **세 개**(개인·학교·기타)를 한 비서가 함께 보길 원한다.
저장소는 공개이고 계정 정보는 개인정보이므로, 인증 파일과 계정 주소가 저장소에 들어가지 않아야 한다.

## 결정

### 1. 인증: OAuth 설치형 앱 흐름을 직접 구현

- `google-auth-oauthlib` 같은 라이브러리를 쓰지 않고, 표준 흐름(PKCE + 루프백 리디렉션)을 `app/google/auth.py`에 직접 구현했다.
  - 이유: 런타임 의존성을 늘리지 않고(동기 `requests`가 딸려 온다), 흐름을 설명할 수 있어야 한다(CLAUDE.md 1절).
  - 로그인은 `python -m app.google.login <계정 이름>`으로 계정마다 한 번씩 한다. 브라우저를 열고 루프백 주소로 인증 코드를 받는다.
- 토큰은 계정마다 `private/google_token_N.json`에 따로 둔다. OAuth 클라이언트 파일 하나(`private/google_client.json`)를 세 계정이 공유한다.
- 실행 중에는 refresh_token으로 access_token만 갱신한다(만료 2분 전 미리). 토큰·클라이언트 비밀값은 로그와 오류 메시지에 넣지 않는다.
- `invalid_grant`(권한 철회, 테스트 모드 7일 만료)는 "다시 로그인하세요"로 안내한다. **동의 화면을 프로덕션으로 두면 7일 만료가 없다.**

### 2. 계정 여러 개를 하나로 묶기

- `GoogleAccounts`가 계정 목록을 들고, 조회는 연결된 계정을 모두 돌아 합친다. 결과에는 계정 이름표(`[학교]`)를 붙이고, 연결된 계정이 하나면 붙이지 않는다.
- **한 계정이 실패해도 나머지는 그대로 보여 준다.** 실패한 계정 이름만 한 줄로 알린다.
- 쓰기(일정 등록 등)는 기본 계정 하나를 고른다. 사용자가 계정을 지정하면 그 계정에 쓴다.
- 계정 주소(이메일)는 저장하지 않는다. 구분은 사용자가 붙인 이름(개인·학교·기타)으로만 한다. 이름은 `config.toml`에 있고, 바꾸려면 `private/local.toml`에서 덮어쓴다.

### 3. 캘린더

- 조회·빈 시간 찾기는 즉시 실행, 등록·수정·삭제는 확인 버튼을 거친다 (7절).
- **일정 식별자는 모델에 넘기지 않는다.** 수정·삭제는 날짜와 제목 일부로 찾고, 여러 개가 맞으면 후보를 보여 주며 되묻는다. 모델이 잘못된 ID로 다른 일정을 지우는 일을 구조적으로 막는다.
- 등록 확인 문구에 겹치는 일정을 함께 보여 준다. 아침·저녁·주간 브리핑에도 겹침을 따로 표시한다.
- 빈 시간은 연결된 계정 전체를 합쳐 계산한다(09~22시 기준). 종일 일정은 하루를 채운 것으로 본다.

### 4. 메일 (Inbox Zero 설계 참고, 코드는 옮기지 않음)

Inbox Zero는 AGPL이므로 **코드를 보지 않고 설계 아이디어만** 가져왔다 (절대 규칙 10).

- 유형은 사용자가 등록한 것만 쓴다. 매칭(발신자·도메인·키워드)은 전부 코드가 한다. 유형별 동작은 6절 표 그대로다.
- **휴지통 이동은 규칙 엔진만 한다.** 모델 도구에는 휴지통·삭제·발송이 아예 없다. 영구 삭제는 구현하지 않았다.
- 보호 목록: 교수님·지원 기업 유형으로 등록된 발신자·도메인과 `private/local.toml`의 `protected_domains`는 어떤 규칙에서도 휴지통으로 가지 않는다. 막혔다는 사실을 알림에 적는다.
- 저녁 브리핑에 정리 내역과 [메일 정리 되돌리기] 버튼을 붙인다. 버튼은 알림 이벤트의 `meta["buttons"]`로 전달되어, 발송 경로는 알림 게이트 하나를 유지한다 (4-1절).
- 답변 대기(Reply Zero 참고): 교수님·학과 메일은 답변 대기로 등록하고, 같은 스레드에 보낸 메일이 생기면 자동 해제한다. 기한이 지나면 브리핑에서 한 번만 상기한다.
- 답장 초안은 Gmail 임시보관함에 저장만 한다. 발송 주소(`/send`)는 어디에서도 호출하지 않으며, 테스트로도 확인한다.
- 수집은 `history.list` 커서로 새 메일만 가져온다. 커서가 만료되면(404) 최근 하루치로 대체한다. 처음 연결한 계정은 그 시점부터 본다(지난 메일을 한꺼번에 알리지 않는다).
- 실패는 `collector_failed` 이벤트로 보고하고, 다른 계정 수집은 계속한다.

## 원본·기존 설계와 다르게 한 점

- 인증 라이브러리를 쓰지 않고 흐름을 직접 구현했다. 대신 토큰 저장 형식과 갱신 시점을 우리가 정했다.
- 계정이 여러 개라는 점을 처음부터 자료 구조에 넣었다. 단일 계정 예제와 달리 조회 결과에 계정 이름표가 붙고, 실패가 계정 단위로 격리된다.
- 메일 유형 판단을 모델에게 맡기지 않았다. 모델은 등록된 유형 목록을 읽고 규칙 추가를 제안할 뿐, 분류 자체를 바꾸지 못한다.
- 일정·메일 모두 식별자를 모델 컨텍스트에서 뺐다. 잘못 지우는 사고를 막고, 프롬프트도 짧아진다.
