## 4. 운영 방법

- 실행: `py -3.14 -m uv run python -m app.main` (종료는 Ctrl+C)
- 테스트: `py -3.14 -m uv run pytest`
- 설정: `config.toml` (공개, 개인정보 없음). 개인 설정 덮어쓰기는 `private/local.toml`
- 개인 폴더 `private/` (git 제외, 개인정보와 비밀값은 전부 여기에만 둔다)
  - `.env`: 봇 토큰, 모델 키 등 비밀값
  - `profile.md`: 이름·호칭·학교·시간표 등 사용자가 직접 작성 (호칭도 여기서 읽는다)
  - `local.toml`: 지역·주소처럼 개인을 알아볼 수 있는 설정값 (없어도 된다)
  - `assistant.db`: 할 일·알림·예약·대화·보관함·마지막 위치, `memory.md`: 비서 기억
- 빈 양식은 `templates/`에 있다 (`env.example`, `profile.example.md`, `local.example.toml`). 새 컴퓨터에서는 이 세 개를 `private/`로 복사해 채운다.
- 모델 호출 경로: 현재 **결제 미연결 무료 티어 키**로 운영 중 (`[llm.gemini] billing_enabled = false`, `allow_free_tier = true`). 무료 티어에서는 입력 내용이 Google 제품 개선에 쓰일 수 있다. 결제를 연결하면 두 값을 `true` / `false`로 바꿔 B안으로 돌아간다.

## 5. 다음 작업

### 날씨 위치 (사용 방법)

1. 인증키는 `private/.env`의 `WEATHER_API_KEY`에 등록되어 있다 (2026-09-18, 실제 호출 확인).
2. 텔레그램 대화에서 클립(첨부) → 위치 → "현재 위치 전송"을 한 번 보내면 그 좌표를 기준으로 본다.
3. 이동 중에도 따라가려면 같은 메뉴에서 "실시간 위치 공유"를 켠다. 공유하는 동안 갱신이 자동으로 들어온다.
4. 위치를 보낸 지 24시간이 지나면 `private/local.toml`의 고정 동네로 돌아간다. 고정 동네를 적어 두면 위치를 보내지 않은 날에도 브리핑에 날씨가 들어간다.
5. 좌표는 `private/assistant.db`에만 한 줄로 저장되고 로그에 남지 않는다. 끄려면 `config.toml`의 `[weather] follow_telegram_location = false`.

### 5단계: Google 연동 (다음 진행)

- 캘린더: 조회·빈 시간 찾기, 등록·수정·삭제(확인 버튼), 일정 충돌 알림, 브리핑에 오늘·내일 일정 추가
- Gmail: 변경분 폴링(history 커서) → 규칙 엔진(발신자·도메인·키워드는 코드, 설명형 유형만 모델이 등록 목록 안에서 분류) → 유형별 알림·후속 동작
  - 휴지통 이동은 규칙 엔진만 하고, 보호 목록(학교·지원 기업)은 코드에서 차단한다. 영구 삭제는 없다.
  - 답변 대기 등록·자동 해제·기한 후 1회 상기
  - 저녁 브리핑에 정리 내역과 [되돌리기] 버튼
  - 답장 초안은 임시보관함 저장만 한다 (발송 기능 없음)

### 6단계: eClass 수집기

- 로그인 세션 재사용, 할 일 목록(과제·시험·온라인 강의) 수집 → 할 일 자동 등록, 공지·알림함·학사일정 수집
- 마감 변경 감지 후 1회 알림, 급한 소식(휴강·시험 변경·24시간 내 마감)은 즉시 알림
- 실패 분류(로그인 실패, 추가 인증·CAPTCHA, 구조 변경, 네트워크), 로그인 연속 2회 실패 시 중단
- 학교 주소 등 학교를 특정하는 값은 공개 저장소 밖의 로컬 설정에 둔다

### 7단계: 감시 기능

- 인턴 지원 단계·서류·마감 추적(D-14, D-7, D-3), 지정 채용 페이지 공고 감시, 교환학생 공지 감시

### 8단계: 운영

- Docker 이미지(arm64), Oracle Cloud A1 배포, 야간 백업, 수집 실패 재알림 주기, 로그 정리

## 6. 나중에 처리할 것

- `collector_failed`의 ref_id가 원인별로 고정이라 같은 원인의 실패는 한 번만 알린다. 8단계에서 재알림 주기를 정한다.
- google-genai가 Python 3.17에서 제거될 문법을 쓴다는 경고가 난다. 현재 동작에는 영향이 없고, SDK 업데이트 때 확인한다.
- 대화 요약에 "진행 중인 요청: 없음" 같은 불필요한 줄이 섞일 수 있다. 요약 프롬프트를 조정한다.
- 무료 티어에서는 Gemini 웹 검색(그라운딩) 호출이 제한될 수 있다. 실제 사용에서 막히면 별도 검색 API로 바꾼다.
- 보관함 검색은 낱말 포함 방식이다. 항목이 많아져 느려지면 SQLite FTS5로 바꾼다.
- 봇은 사용자가 실행해 둔 동안만 동작한다. 상시 운영은 8단계(서버 배포)에서 해결한다.

## 7. 개인정보 관리

- 저장소는 공개 상태다. 개인을 알아볼 수 있는 값과 모든 키는 `private/` 폴더 한 곳에만 두고, 이 폴더는 통째로 git에서 제외된다 (2026-09-18 정리).
- 저장소에 올라가는 파일에는 "사용자", `{honorific}`, 예시 값 같은 범용 표현만 쓴다. 코드와 프롬프트는 호칭을 실행할 때 `private/profile.md`에서 읽는다.
- 앞으로 생기는 개인 파일(구글 OAuth 토큰, eClass 세션, 서비스 계정 키 등)도 모두 `private/` 안에 만든다.
- 2026-09-18 정리 이전의 커밋 기록에는 이름·학교 정보가 남아 있다. 지우려면 기록을 다시 쓰고 강제 푸시하거나, 저장소를 비공개로 바꿔야 한다 (사용자 결정 필요).

## 8. 개발 환경 메모 (Windows 개발 PC)

- Python 3.14.7(시스템 설치본)을 쓴다. 이 PC는 `AppData\Roaming` 아래 junction 실행이 막혀 있어 uv 관리형 Python을 쓰지 않는다 (사용자 uv 설정: `python-downloads = "manual"`).
- uv는 PATH에 없어서 `py -3.14 -m uv ...`로 실행한다.
- 다른 Python 3.13 설치본은 표준 라이브러리 폴더가 없는 손상 상태다. uv가 경고를 띄우지만 무시해도 된다.
- 프로젝트 폴더는 OneDrive 동기화 폴더 안에 있다 (사용자 결정). DB 손상이 생기면 재검토한다.
